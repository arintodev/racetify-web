This feature covers generator templates, font availability, previews, batch generation, generated
document downloads, and certificates. Public certificate display is specified in
[Public Content](./2026-11-10-19-17-api-contract-public.md).

---

## 1. Scope

| Screen | Route | Data |
| --- | --- | --- |
| Bib generator | `/events/[eventId]/bib-generator` | Templates, variable mapping, preview, batch |
| Certificates | `/events/[eventId]/certificates` | Certificate rows, generation, revocation, download |

Out of scope:

- Template visual editing. v1 manages template metadata and accepts SVG/JSON content supplied by the
  organizer or generated by a future editor.
- Public certificate lookup and verification — public contract.
- Certificate search rate limiting and privacy — public contract.

## 2. Permissions

| Action | Permission |
| --- | --- |
| View templates, fonts, previews, and generated documents | `event:generators:manage` |
| Create/update/delete templates | `event:generators:manage` |
| Run bib and certificate generation batches | `event:generators:manage`, `event:certificates:generate` |
| View certificates | `event:certificates:view` |
| Generate certificates | `event:certificates:generate` |
| Revoke certificates | `event:certificates:revoke` |
| Download organizer copies | The matching view/generate permission |

Certificate generation requires both `event:certificates:generate` and access to the template. Bib
batch generation requires `event:generators:manage`.

## 6. Business rules

### Templates

- A template belongs to one event and one scope (`bib` or `certificate`).
- `format = svg` accepts sanitized SVG; `format = json` accepts the structured template format. Both
  are limited to 1 MB.
- SVG is sanitized server-side: no scripts, event handlers, external styles, external images, or
  `<foreignObject>`. Unsafe templates → `422 template_unsafe`.
- `width` and `height` are positive; `unit` is `mm` or `px`.
- Updating content increments `version` atomically. Existing generated documents keep their original
  version.
- A template used by a running or completed generation job can be updated; new jobs use the new
  version. Deleting a template referenced by any generated document or certificate →
  `409 template_in_use`; archive instead.
- Variables are declared in the template and mapped from participant/registration/event data:
  `bibNumber`, `bibName`, `firstName`, `lastName`, `raceName`, `categoryName`, `eventName`,
  `eventLogo`, `sponsorLogo`, `certificateNumber`, `issueDate`, `finishStatus`.
- Unknown variables → `422 unknown_template_variable`.

### Preview

- `POST /generator-templates/{templateId}/preview` accepts:
  ```json
  {
    "registrationId": "018f...",
    "participantId": "018f...",
    "overrides": { "sponsorLogo": "018f...storage-object" }
  }
  ```
  Exactly one of `registrationId` or `participantId` is required for a participant-based preview;
  a template-only preview is allowed when the template declares placeholders.
- The server renders a representative preview and returns a signed URL. Previews are cached for
  15 minutes and never persisted as generated documents.
- Preview does not create certificates or consume certificate numbers.

### Fonts

- `GET /fonts` returns fonts available to the event, including organization-scoped fonts.
- Font management is read-only in v1; fonts are seeded or provisioned by platform administration.
- Only `active` fonts are returned to generation. A disabled font referenced by a template →
  `422 font_unavailable`.
- Font files are never exposed directly; previews use a signed URL.

### Bib batch generation

`POST /generated-documents`:

```json
{
  "type": "bib",
  "templateId": "018f...template",
  "recipientFilter": {
    "raceId": "018f...race",
    "categoryId": null,
    "registrationIds": null,
    "status": "confirmed"
  }
}
```

- `recipientFilter` selects registrations in the event. At least one of `raceId`, `categoryId`, or
  `registrationIds` is required; an empty filter would target the whole event and is rejected with
  `422 recipient_filter_required`.
- The server resolves recipients, rejects the request if the count exceeds 10,000
  (`422 batch_too_large`), and returns `202` with a job.
- The job renders one output per registration, writes files to object storage, and produces a ZIP.
- Idempotency: the same `Idempotency-Key` returns the same job; a new key with the same filter
  creates a new job.
- Downloads are signed and expire after 15 minutes. A completed job can be downloaded repeatedly by
  requesting a fresh URL.

### Certificate generation

- Certificate generation requires a certificate-scoped template and `event:certificates:generate`.
- It uses the same recipient filter, plus `onlyConfirmed: true` by default.
- The server assigns a globally unique `certificateNumber` from a configured sequence/prefix. The
  client never supplies a certificate number.
- Each generated certificate row starts as `pending`, becomes `issued` when the file is written, and
  is rolled back to `pending` if rendering fails.
- Re-running generation for the same registration returns the existing certificate if one exists and
  is not revoked (`200` with the existing row) rather than creating a duplicate. This requires a
  unique constraint on `(event_id, registration_id)` or an equivalent idempotency rule; add it if the
  product confirms one certificate per registration.
- Certificate numbers are unique globally so `/cert/{certificateNumber}` is unambiguous.
- Revocation:
  - Sets `status = revoked` and `revokedAt`; it does not delete the row or the file.
  - Idempotent: revoking an already revoked certificate returns `200`.
  - Revoked certificates are hidden or shown as a safe state publicly.
  - Organizers with `event:certificates:view` may still download the organizer copy for records.
- Certificates are never generated for cancelled or refunded registrations.

### Generated documents

- Job statuses: `pending → processing → completed | failed | cancelled`.
- Progress is updated incrementally; the client polls or refetches.
- A failed job reports a stable error code and a count of failed recipients; successfully generated
  rows are retained.
- Cancelling a pending job stops new work; completed rows remain.
- Generated files are stored in object storage with a retention policy (recommended 90 days for
  batch ZIPs, longer for certificates). The API returns signed URLs only.

## 7. Error codes

| HTTP | `code` | Condition |
| --- | --- | --- |
| 404 | `template_not_found` | Unknown/cross-tenant template |
| 404 | `certificate_not_found` | Unknown/cross-tenant certificate |
| 404 | `generated_document_not_found` | Unknown job |
| 409 | `template_in_use` | Delete a referenced template |
| 409 | `certificate_already_exists` | Duplicate certificate for a registration |
| 409 | `generated_document_not_ready` | Download before completion |
| 409 | `job_cancelled` | Operation on a cancelled job |
| 422 | `template_unsafe` | Unsafe SVG/HTML content |
| 422 | `template_too_large` | Over 1 MB |
| 422 | `unknown_template_variable` | Variable not in the catalog |
| 422 | `font_unavailable` | Referenced font is disabled/missing |
| 422 | `recipient_filter_required` | Empty recipient filter |
| 422 | `batch_too_large` | Over 10,000 recipients |
| 422 | `invalid_template_scope` | Bib job with a certificate template or vice versa |
| 409 | `certificate_not_revocable` | Certificate is pending/failed |

## 8. Frontend mapping

| Screen / component | Query | Key |
| --- | --- | --- |
| Bib templates | `GET /generator-templates?scope=bib` + `GET /fonts` | `["event", eventId, "templates", "bib"]`, `["event", eventId, "fonts"]` |
| Template preview | `POST /generator-templates/{id}/preview` | `["event", eventId, "template-preview", templateId, registrationId]` |
| Bib batch | `POST /generated-documents` + `GET /generated-documents/{id}` | `["event", eventId, "generated-documents", jobId]` |
| Certificate table | `GET /certificates` with filters | `["event", eventId, "certificates", filters]` |
| Certificate detail | `GET /certificates/{id}` | `["event", eventId, "certificate", certificateId]` |
| Certificate generation | `POST /certificates/generate` + job status | `["event", eventId, "certificates", "job", jobId]` |

Invalidation:

- Template create/update/delete → templates query.
- Bib batch completion → generated documents query; no participant changes.
- Certificate generation completion → certificates query, event overview.
- Certificate revocation → certificate detail, certificates list, public certificate query.

UI rules:

- The generator screen uses the template list, variable mapping panel, participant preview, and batch
  dialog from the route map.
- The certificate screen uses server-side filtering and pagination; generation and revocation show
  job/dialog progress.
- Download actions request a fresh signed URL; an expired URL triggers a refetch.
- Without `event:generators:manage`, the bib generator is hidden.
- Without `event:certificates:view`, the certificate screen is hidden.
- Generate and revoke actions are hidden without their specific permissions.
- The UI never displays a raw template SVG or storage key.

## 9. Acceptance criteria

1. Templates list by scope and render server-side previews.
2. Unsafe SVG and oversized templates are rejected.
3. Fonts available to the event are returned; disabled fonts are not offered.
4. Bib batch generation resolves recipients, enforces limits, runs as a job, and produces a signed
   ZIP.
5. Certificate generation assigns globally unique numbers and is idempotent per registration.
6. Revocation is idempotent, preserves the record, and changes the public state.
7. Certificate rows include participant, race, category, number, status, and issued date.
8. Downloads require a completed job and return short-lived URLs.
9. Cross-tenant template/certificate/job IDs return `404`.
10. All screens typecheck against the generated client and respect permissions.
