# Google OAuth Sign-In

Status: implemented; backend and both apps build green. No Google credentials were exercised (no
network calls in verification).

## Flow

1. `GET /v1/auth/providers` reports `{ google: boolean }` based on the server configuration.
2. The login/register pages render "Continue with Google" only when that flag is true.
3. The button navigates to `/api/v1/auth/oauth/google/start?redirect=<relative-path>`.
4. The API creates a random `state` and PKCE verifier, stores `{verifier, redirect}` in Redis for
   10 minutes, sets a short-lived HttpOnly `__Host-racetify_oauth_state` cookie, and redirects to
   Google's consent screen with `S256`.
5. Google redirects to `GOOGLE_REDIRECT_URL` (`/v1/auth/oauth/google/callback`):
   - the callback state must match the HttpOnly state cookie (login CSRF defense),
   - the state record is read and deleted (single use),
   - the code is exchanged server-side with the verifier,
   - the profile is read from Google's userinfo endpoint,
   - an unverified email is rejected (`oauth_email_unverified`),
   - the account is resolved by Google `sub`, then by verified email, else created,
   - the social account is linked and a normal opaque session is issued/rotated.
6. The callback redirects to `{APP_ORIGIN}{redirect}` with the session cookie.
   Failures redirect to `/login?error=<code>` and never include provider details.

## Account rules

- Existing `identity.social_accounts` row for `(google, sub)` → sign in that user.
- No social row but a user with the same verified email → link the social account and sign in.
  This is safe because Google verified the email and the API requires `email_verified: true`.
- No user → create a password-less user with `email_verified_at = now()`, then link the social row.
- Suspended/deleted users are rejected without a session.
- If an existing session cookie arrives at the callback, it is revoked and replaced, keeping the
  session-fixation rule from the general contract.

## Configuration

| Variable | Purpose |
| --- | --- |
| `GOOGLE_CLIENT_ID` | Google OAuth client ID |
| `GOOGLE_CLIENT_SECRET` | Google OAuth client secret |
| `GOOGLE_REDIRECT_URL` | Registered callback URL **through the app's same-origin proxy**, e.g. `https://app.racetify.com/api/v1/auth/oauth/google/callback` (dev: `http://localhost:3000/api/v1/auth/oauth/google/callback`) |
| `APP_ORIGIN` | Where the callback redirects after login (default `http://localhost:3000`) |

Google Cloud console must list the exact callback URL.

**The callback must go through the organizer app origin, not the API host.** The callback response sets
the session cookie; routing it through `https://app.racetify.com/api/...` (the Next.js rewrite) makes
that cookie first-party for the app. A callback registered directly on the API host would set the
cookie for the wrong origin and the app would not see the session.

## Error mapping

| API code | Login page message |
| --- | --- |
| `oauth_not_configured` | Google sign-in is not available right now. |
| `oauth_email_unverified` | Google has not verified this email address. |
| `account_suspended` | This account is suspended. Contact your workspace owner. |
| any other failure | Google sign-in could not be completed. Try again. |

The start endpoint returns `503 oauth_not_configured` when the client id/secret/redirect URL are
absent, matching the previous stub contract.

## Verification

- Backend: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --locked -- -D
  warnings`, `cargo build --workspace --locked`, `cargo test --workspace --locked`,
  `cargo run --locked -p api --bin openapi`.
- Frontend: contract sync/generate, `pnpm typecheck`, both lints, both builds.
- Live sign-in requires Google credentials, the callback URL registered in Google Cloud, Redis for
  the state store, and the API/database running. None of that was executed here.
- `GET /v1/auth/providers` returns `{ "data": { "google": false } }` without credentials, so the
  buttons stay hidden.
